Which HubSpot workflows can I build without Operations Hub Professional?

Short answer

Nearly all of them. Every workflow in this pack runs on native actions at Sales, Marketing or Service Hub Professional: rotation, property edits, tasks, branches, delays, internal notifications, Slack alerts and marketing emails. No code, no Operations Hub, no third-party tool. Operations Hub, now sold as Data Hub, adds custom coded actions, the Format data action and native webhooks on top. Expect twenty to forty-five minutes per workflow.

What a spec looks like

Every spec follows the same nine sections, so a team reads one and knows how to read all of them.

  • Outcome, when to use it and when not to
  • Prerequisites: properties, lists, tiers, with the JSON to create them
  • Enrollment and re-enrollment, then every step with its parameters
  • Known pitfalls, a test plan, variants, and the YAML build spec

What breaks, and how the specs prevent it

Native rotation does not rebalance, and it does not replace a leaver

Rotate record to owner distributes by assignment count across the pool as it stands at run time. Adding a rep does not rebalance what came before, a rep on holiday still gets their turn, and a deactivated user is skipped rather than replaced. Pool membership is a maintenance job, not a setting.

A workflow cannot stop a bad record from being created

Workflows react after the record exists, so every required-field and association check here is detect and flag, never block. The create-form setting gates manual creation in the interface only, not imports, API calls or records made by other workflows. Plan a review queue, and expect that queue to need a second workflow to clear itself.

Some actions do not exist at any tier

There is no merge action, no Remove from workflow action, and no native wait-until-a-task-is-complete step. There is no manager-of-the-owner lookup below Enterprise teams either, which is why several specs here carry an explicit Manager or Escalation contact property. Operations Hub does not add these. Knowing they are missing saves the afternoon you would spend looking.

What this bundle builds

The question underneath this page is a budget question. Someone read a blog post, saw a custom coded action in the screenshots, and now believes the automation they need costs another line on the renewal. Usually it does not.

This bundle is the working set of a portal that runs on Sales, Marketing or Service Hub Professional. Leads get an owner within minutes and the owner gets a task. Deals pick up the right next step at each stage, chase their own missing fields, and hand off cleanly the moment they close. Contacts move from lead to MQL to SQL on a documented threshold, with the sales ping attached. Tickets route by product and by channel, and a missed first response wakes somebody up. Feedback gets acted on instead of read.

The last component is the one people skip and then regret. Six flags catch the records that quietly break everything else: a contact with no company, a deal with no company, a ticket with no contact, a company with no domain, a contract with no end date. None of them needs code. All of them need a real owner on the other end of the queue.

How the pieces fit together

Routing first, because almost everything downstream assumes a record has an owner. Start with the flat rotation, then add the territory version once the territory field is reliable, then the lifecycle and trial-tier routes on top. The deactivated-owner cleanup comes last and depends on an admin habit, not on a property.

Deal hygiene next, since stage tasks and forecast category both branch on your pipeline’s internal stage names, which you should confirm once and reuse everywhere. The closed-won specs share three properties, Onboarding Owner, CS Handoff Notes and a sent flag, so build the handoff task before the summary email and the checklist.

Lifecycle sits beside that and depends on one number, the score threshold, kept in a single workflow so sales gets one answer. The ticket set needs SLA goals configured on the help desk pipeline first, or the breach alert enrolls nothing and fails quietly. Leave the flags for last: they depend on nothing, and by then you know which gaps your portal actually has.

Questions admins ask

Do HubSpot workflows require Operations Hub Professional?

No. Workflows come with the Professional and Enterprise tiers of Marketing, Sales and Service Hub, and that action list already covers rotation, property edits, tasks, internal notifications, delays, branches, list membership and marketing emails. Operations Hub, now sold as Data Hub, adds a specific set of actions on top rather than unlocking automation itself.

What does Operations Hub Professional add to a workflow?

Three things you can see in the action picker: custom coded actions in JavaScript or Python, the Format data action for string and number cleanup at scale, and native webhooks for outbound calls. The cross-object property copy across an association sits there too. The specs that need those live in the Operations Hub power pack, not here.

When is Operations Hub worth buying?

When you need a lookup or a search that the filter language cannot express, text normalization at a volume nobody will do by hand, or a call out to another system. If all you need is a computed number, a calculated property gets you there on any Professional tier. Buy it for the code, not for the automation.

Can a workflow enforce a required field?

Not as a hard block, on any tier. Six specs here take the honest route: detect the gap at creation, write a status property, add the record to a review list and assign a task to a real owner. Pair that with required properties on the form or on the pipeline stage, which is the only preventive control HubSpot offers.

Which hub do the ticket specs in this bundle need?

Service Hub Professional. Tickets only exist where Service Hub is provisioned, and the SLA goals that the first-response breach alert reads are set on the help desk, not on a Sales Hub pipeline. Sales Hub Professional does not grant them. The same applies to the NPS specs, since customer loyalty surveys are a Service Hub Professional feature.
