Custom object required-field enforcement on creation

Data qualityCustomData Hub EnterpriseIntermediate~25 min to buildFull spec

Outcome. New custom object records missing a required field get flagged and routed to a task immediately, instead of an incomplete record sitting unnoticed until someone downstream tries to use it.

When to use it, when not to

  • UseUse it on any custom object where a small set of fields must be filled in for the record to be usable, an approval, a report, an integration export.
  • UseUse it when the custom object is created through more than one path (manual entry, import, an integration) so a single form cannot guarantee the fields are filled in.
  • SkipDo not use it as a substitute for making the property required at the form or record-creation level if your object supports that. Workflow-based enforcement is a safety net for paths that bypass the form, not the first line of defense.
  • SkipDo not use it if the object has no meaningful required-field concept to flag. A purely descriptive object with no downstream dependency on completeness does not need this.
