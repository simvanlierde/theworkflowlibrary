Library / Sales ops / sales-ops-001

Auto-enroll contact in sales sequence when lead status becomes Sales Qualified Lead

Free, completeSales opsContactSales Hub ProfessionalSimple~25 min to build

One of the 10 free specs. All nine sections are open on this page, nothing is held back. Install it into your portal against an email, or build it by hand from what you read here.

Outcome. A contact starts a personal sales sequence automatically the moment a rep or a scoring rule marks them as sales-qualified, with no manual "select and enroll" step.

When to use it, when not to

  • UseUse it when SDRs currently open each qualified contact and manually click "Enroll in sequence." This removes that click.
  • UseUse it when your Lead status values are consistent and someone (rep or a scoring workflow) reliably sets the qualified value.
  • SkipDo not use it if multiple sequences could apply depending on persona or product interest. Branch first (see Variants) or you will enroll everyone into one generic sequence.
  • SkipDo not use it for contacts without a real owner. Sequence emails send from a specific HubSpot user; an unowned contact has nobody to send from and the action fails silently for that record.

Prerequisites

  • Property: Lead status (internal name hs_lead_status), object contact, this is a default HubSpot enumeration property. Add a custom option Sales Qualified Lead to it if it does not already exist. Why: this is the value the trigger reads.
  • A built sequence in Sales Hub (Automation > Sequences), with at least one email template and, optionally, manual task steps. Why: the enrollment action needs a live sequence to point to.
  • Every contact that can reach this trigger must have a Contact owner set, and that owner must be an active Sales Hub seat with sequences access and a connected personal inbox. Why: Enroll in sequence sends from the chosen sender; no connected inbox means no send.
  • Confirm the contact has a valid, opted-in email address. Sequences respect marketing and one-to-one email unsubscribe status.

Enrollment

  • Trigger type: event-based.
  • Criteria: Lead status property changed to value Sales Qualified Lead. Add a filter Email address is known and Contact owner is known to keep unreachable or unowned contacts out.
  • Re-enrollment: on, re-enroll only if Lead status changes back to Sales Qualified Lead after having left that value first (this covers a contact that goes qualified, cools off, and gets re-qualified later).
  • Suppression: exclude contacts in the static list Do not sequence and exclude anyone already in an open deal past the Demo stage, so an AE-owned deal in flight does not get an SDR sequence layered on top. Associated deal properties are available as enrollment filters in contact-based workflows on every tier; the only tier-gated triggers are page views and CTAs (Marketing Hub Professional) and quote-based triggers (Commerce Hub Professional) (https://knowledge.hubspot.com/workflows/set-filter-enrollment-triggers).

Steps

  1. Filter branch: Contact owner is known AND Email address is known.
    • If false: Send internal email notification to sales ops owner, subject "Qualified lead missing owner or email: {{contact.hs_object_id}}". End workflow for this branch.
  2. If/then branch: Product interest is known (see Variants for persona branching). For the base version, skip branching and go straight to step 3.
  3. Enroll in sequence: sequence = "SQL - First Outreach", sender = Contact owner, send sequence emails from the owner's connected inbox.
  4. Set property value: Date entered sequence = current date (custom property, create if it does not exist, useful for reporting cycle time).
  5. Create task: type "Call", title "Sequence kickoff call - {{contact.firstname}}", due same day, assigned to Contact owner.

Known pitfalls

  • A contact can be actively enrolled in only one sequence at a time. If this workflow fires while the contact is already mid-sequence from another workflow, enrollment is skipped, not queued. Check workflow history for "not enrolled - already in sequence" entries.
  • If the contact owner's inbox connection breaks (token expired, mailbox disconnected), the sequence step fails silently for that contact and no error surfaces to the rep unless they check the sequence's own performance tab.
  • Sequences do not observe deal stage automatically. Pair this with sales-ops-008 (auto-unenroll when a deal is created) if you do not want sequence emails continuing after the contact becomes an active deal.
  • Adding a custom value to hs_lead_status changes a shared default property. Confirm no other workflow or report depends on the existing value set before adding options.
  • Re-enrollment on a property that flips back and forth quickly (status bouncing) can burn through sequence steps for a contact repeatedly. Add a suppression list for anyone re-enrolled more than twice in 30 days if this becomes a problem.

Test plan

  1. Create a test contact with a valid test-safe email address, set Contact owner to your own test user, and set Lead status to Sales Qualified Lead.
  2. Open Automation > Workflows > this workflow > History tab, confirm the contact enrolled within a minute and the branch it took.
  3. Check the contact's record timeline for the "Enrolled in sequence" event and confirm the sequence name matches.
  4. Confirm the call task appears in the owner's task queue due today.
  5. Change Lead status away from and then back to Sales Qualified Lead, confirm re-enrollment behaves as expected (or is skipped if still mid-sequence).

Variants

  • Persona-based routing: add an If/then branch on Product interest before the enroll action and point each branch to a different sequence (see sales-ops-043).
  • Deal-based instead of contact-based: enroll a deal's primary contact when the deal enters a specific pipeline stage, same enroll action, trigger on deal stage instead.
  • Team-based sender: instead of Contact owner, send from a fixed team inbox for high-volume SDR pods that share sequence sending.

Build spec

trigger:
  type: event-based
  event: property_changed
  property: hs_lead_status
  criteria:
    - hs_lead_status: equals "Sales Qualified Lead"
    - contact_owner: is_known
    - email: is_known
  reenrollment: true
  reenrollment_property: hs_lead_status
  suppression_list: "Do not sequence"
actions:
  - type: if_then_branch
    condition: contact_owner_known AND email_known
    if_false:
      - type: send_internal_email_notification
        to: sales_ops_owner
        subject: "Qualified lead missing owner or email: {{contact.hs_object_id}}"
    if_true:
      - type: enroll_in_sequence
        sequence: "SQL - First Outreach"
        sender: contact_owner
      - type: set_property_value
        property: date_entered_sequence
        value: current_date
      - type: create_task
        task_type: call
        title: "Sequence kickoff call - {{contact.firstname}}"
        due: today
        assigned_to: contact_owner
